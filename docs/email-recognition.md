# 邮件识别与关联

## 决策顺序

1. 根据主题与发件人召回候选，已知招聘平台只帮助召回，不证明雇主。
2. 按邮件目的排除推广、课程、宣讲、账户验证和无个人进度内容。
3. 以当前主题、邀请或结果决定阶段；拒信和录用结论优先于背景中的感谢投递。
4. 提取可靠公司和岗位，再在对应求职模块中关联申请。
5. 解析和关联达到 90% 且唯一时自动写入，否则保留原因供核对。

## 身份与岗位

公司字段优先于平台标题。主题中的“重要”“紧急”“External”等标签会被排除，真实雇主可从其后的招聘项目名称提取。未知域名不会被直接翻译或猜作公司。

岗位支持显式字段及“应聘／申请／投递……【岗位】职位”等自然写法。平台和回执后的推荐职位不参与当前申请；测评名称只作弱线索。

关联优先级为：同公司申请编号、历史会话或回复引用、完整岗位、正文唯一岗位线索、同公司唯一在途申请。公司别名和招聘批次可归一化，但城市、业务和研发／综合等方向必须保留。

## 示例

| 场景                                                     | 结果                                 |
| -------------------------------------------------------- | ------------------------------------ |
| 已有用友的江苏区申请，带“重要”标签的测评明确写江苏区岗位 | 自动关联该条申请，记录测评与待办     |
| 同公司有江苏、上海两条，通知只写其中一条完整岗位         | 只更新明确命中的岗位                 |
| 公司唯一在途申请，测评未写岗位                           | 可以自动关联                         |
| 同公司多个岗位，没有岗位、编号或会话线索                 | 待确认并说明歧义                     |
| 亚信回执只确认简历入库，未写岗位                         | 识别为投递回执，保留待确认以补充信息 |
| 课程、推荐职位或条件说明提到面试                         | 不作为当前阶段                       |

测评、笔试和面试不单独创建未知岗位；只有可靠、完整、无歧义的投递回执自动新建。

## 时间与重放

显式截止日期优先。邮件明确提供“测评有效期72小时”“请在3天内完成测评”时，以邮件时间换算截止；作答时长、客服响应、点击后才开始的期限和网页发现时间不用于此换算。“开始测评”按钮后面的落款日期不作开始时间。

规则变化时更新 `MAIL_RULES_VERSION`，最近 90 天旧待确认将重新下载正文并解析。已应用、已忽略或已撤销的邮件保留用户决定。重复同步保持事件与待办幂等。
