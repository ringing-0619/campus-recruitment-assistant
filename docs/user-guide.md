# 使用指南

## 开始记录

先在顶部选择“国内秋招”或“美国求职”，然后新增公司和岗位。两个模块的记录、匹配、统计及导入导出相互隔离，切换页面不会移动记录。

建议填写实际投递日期、岗位方向、真实渠道及简历版本，以便分析。未知日期保留为空；邮件发现时间不自动充当真实投递时刻。归档与作废也分别记录，历史统计遵循所选口径。

浏览器扩展先预览、再确认记录。侧栏可编辑公司和岗位、移除误识别项，或者手动补充遗漏岗位。移除后的项目不会在本页后续识别时自动重新提交。

## 邮件和进度

连接 126 邮箱后，在“连接设置”查看最近同步、错误及重试状态。“待确认”展示有歧义的通知及原因；可以选择已有申请，或补全资料后建档。

在“自动更新记录”查看自动变更与撤销。撤销邮件更新意味着忽略这次写入，后续重识别不会自动恢复同一条邮件。

阶段、任务完成与阶段结果分别保存。完成一份测评只表示任务完成，不自动代表通过。拒信、流程结束和 Offer 使用明确的结果信号。

## 目标与分析

为国内和美国模块分别设置每日、每周投递目标。默认不替用户设置数量。历史目标和实际投递日期分别保留；未知日期的旧申请不计入当天新增。

漏斗及对比可按实际投递区间、岗位方向、渠道和简历版本查看。关注样本数、结果覆盖率和耗时中位数，避免将信息缺失的申请当成明确失败。

## 行动与日历

测评、笔试及面试通知可创建待办，支持完成、改期、取消与冲突提示。仅提供相对有效期的邮件按明确期限计算截止时刻；没有时间的通知保留为空。

日历可导出 `.ics`。提醒支持稍后提醒、已跟进和暂停。macOS 桌面通知在“行动与日历”中开启并测试，默认 21:00—08:00 免打扰，具体统计时区可在设置中调整。

## 备份与更新

在连接设置中导出 JSON；导入时先切换到对应模块。升级代码前建议导出，并保留当前数据库备份。更新方法见 [GitHub 操作](github.md)。

浏览器遇到登录、验证码或站点权限要求时，由用户在对应网站完成正常操作。系统不会绕过这些机制。
