# 使用指南

## 安装与启动

需要 Node.js 22.13+ 的 22.x 或 24.x。执行 `npm ci`、`npm run build`、`npm start`，打开 `http://127.0.0.1:43110`。macOS 也可双击项目根目录的 `启动校招助手.command`。使用 `npm run install:agent` 设置登录后启动，`npm run uninstall:agent` 移除自启动；数据和钥匙串凭据保留。

完整桌面集成支持 macOS；其他系统可使用不连接邮箱的核心网页／API。Chrome／Edge 扩展需要 116 及以上版本。

## 独立模拟演示

执行 `npm ci`、`npm run demo`，打开 `http://127.0.0.1:43112`，场景控制页为同一服务的 `/demo`。使用独立临时 SQLite，国内／美国各 20 条虚构申请，日期相对启动日生成。演示不加载生产数据库或迁移文件，并禁用邮箱配置、同步和系统通知。退出后清理，重启恢复初始场景。

控制页依次运行测评通知与重复通知，在看板刷新后检查阶段和待办数量；运行歧义通知后进入“待确认”，选择对应岗位。进度页链接打开的是本地虚构页面，不是真实雇主网站。截图中的反馈率与 Offer 数量均为人为构造的功能验证值。

## 邮箱与扩展设置

在 126 邮箱中开启 IMAP，生成客户端授权码，然后在助手“连接设置”填写邮箱及 16 位授权码。首次读取最近 90 天，之后每 10 分钟增量同步。授权码保存在 macOS 钥匙串；同步只读，不标记已读、不移动、不删除、不回复；超过 2 MB 的候选邮件跳过。

在 `chrome://extensions` 或 `edge://extensions` 开启开发者模式，加载项目 `extension/`，将连接设置中的配对令牌填入扩展选项。只对所需网站授权，先预览核对再记录。更新扩展后重新加载并刷新招聘页；浏览器关闭时监控暂停。

## 开始记录

先在顶部选择“国内秋招”或“美国求职”，然后新增公司和岗位。两个模块的记录、匹配、统计及导入导出相互隔离，切换页面不会移动记录。

建议填写实际投递日期、岗位方向、真实渠道及简历版本，以便分析。未知日期保留为空；邮件发现时间不自动充当真实投递时刻。归档与作废也分别记录，历史统计遵循所选口径。

浏览器扩展先预览、再确认记录。侧栏可编辑公司和岗位、移除误识别项，或者手动补充遗漏岗位。移除后的项目不会在本页后续识别时自动重新提交。

## 邮件和进度

连接 126 邮箱后，在“连接设置”查看最近同步、错误及重试状态。“待确认”展示有歧义的通知及原因；可以选择已有申请，或补全资料后建档。

在“自动更新记录”查看自动变更与撤销。撤销邮件更新意味着忽略这次写入，后续重识别不会自动恢复同一条邮件。

阶段、任务完成与阶段结果分别保存。完成一份测评只表示任务完成，不自动代表通过。拒信、流程结束和 Offer 使用明确的结果信号。

## 目标与分析

为国内和美国模块分别设置每日、每周投递目标。默认不替用户设置数量。历史目标和实际投递日期分别保留；未知日期的旧申请不计入当天新增。

漏斗及对比可按实际投递区间、岗位方向、渠道和简历版本查看。关注样本数、结果覆盖率和耗时中位数，避免将信息缺失的申请当成明确失败。

## 行动与日历

测评、笔试及面试通知可创建待办，支持完成、改期、取消与冲突提示。仅提供相对有效期的邮件按明确期限计算截止时刻；没有时间的通知保留为空。

日历可导出 `.ics`。提醒支持稍后提醒、已跟进和暂停。macOS 桌面通知在“行动与日历”中开启并测试，默认 21:00—08:00 免打扰，具体统计时区可在设置中调整。

## 备份与更新

在连接设置中导出 JSON；导入时先切换到对应模块。升级代码前建议导出，并保留当前数据库备份。更新方法见 [GitHub 操作](github.md)。

浏览器遇到登录、验证码或站点权限要求时，由用户在对应网站完成正常操作。系统不会绕过这些机制。
